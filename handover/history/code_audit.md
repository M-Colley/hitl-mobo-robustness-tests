## A. Findings that change a number or a conclusion

### A1. VERIFIED. The headline cost metric is trajectory search loss, and the paper says it is the deployed design's regret

`scripts/bo_sensor_error_simulation.py:3893,3918` defines `simple_regret_true = y_opt - best_true_so_far`, where `best_true_so_far` is the maximum TRUE value over every design visited so far. `scripts/evaluate_research_question.py:257-285` builds `auc_simple_regret_excess_true_postonset_per_iter` from that column. `scripts/analyse_boba_robustness.py:80,170,181` makes it `excess_sd` and `fragility = excess_sd / opt_z`. `scripts/make_boba_paper_tables.py:92-95` prints the mean of `fragility` as Table 1. So every number in Sections 4, 6, 7 and 8, Table 1, Table 3, Table 4's "excess regret" column, the power law, the descriptor and frag regressions, the confirmatory H1, H2 and H4, and the budget, instrument and robust tables is the excess of the best-visited true value. By the paper's own Equation 5 that quantity is the search-loss term and contains no selection loss at all.

The paper says otherwise. main.tex:356 opens Section 5 with "The regret reported above is the regret of the design a study would deploy". The abstract says "Decomposing the deployed regret locates that cost: 61.8% of it is selection loss". Both sentences are false as written. The decomposition (`scripts/decompose_regret.py:99-120`) is computed on a different quantity, `regret_best_observed` at the final iteration, which is the deployed design. The two are not the same metric, and 61.8% is not a share of the 14.1%.

What is true and can be said (corrected in the third pass). Table 1 reports the post-onset time average of search loss. The final deployed excess is a different quantity with a different time base, so the two cannot be subtracted. The fair comparison is the final deployed excess against the final search excess (`final_simple_regret_excess_true`). On the paper's pooled numbers that ratio is 0.218 against 0.083, and on the real side arms it is 2.45 to 2.64 for the standard process (third pass I1). The same mislabelling affects Table 4's caption, which calls the trajectory metric "the deployment number", and Appendix C with Table 7, which compare search loss only. Section 8's paragraph on augmented EI reports deployed shares and is not affected. `final_inference_simple_regret_excess_true` is logged for every run and `INFERENCE_METRIC` is already defined in analyse_boba_robustness.py:82. Fix. Add a deployed-design column beside every search-loss number, pair it with the final search excess, and rename the current metric "post-onset time-averaged search loss". This is the one change that touches the story.

### A2. VERIFIED. Unit bug in the model-based budget rule (`scripts/budget_split.py:235`)

`sitting_sd = rho * sqrt(gp.likelihood.noise.mean())`. The GP is built with `Standardize(m=1)`, so `likelihood.noise` is the noise variance of the STANDARDISED targets. The posterior mean and SD it is combined with (`eos.latent_mean_sd`, via `gp.posterior`, which untransforms) are in objective units. The two sibling scripts know this and multiply by `outcome_transform.stdvs ** 2` (`scripts/rescore_ship_rules.py:255-256`, `scripts/replay_stopping.py:388`). budget_split.py does not. The rule therefore uses a sitting SD that is wrong by the factor stdvs of the prefix ratings, which is not 1 in general. With `--noise-source truth` the bug is inert. The default is `gp` and the invocation used for the paper is not recorded anywhere in the repository.

Affected numbers. Section 9 "A model-based budget rule inherits the corruption it was meant to fix": +0.005 [−0.011, +0.022] against +0.051 for fixed k, "declines the sitting in 64% of runs", "the worst policy of all at −0.013". Appendix M. The Discussion sentence "Nothing we tried beat fixing k". `tests/test_budget_split.py` passes `sitting_sd` by hand and never exercises `derive_for_run`, so the suite cannot catch it. Fix. One line, `noise * stdvs ** 2` before the sqrt, then rerun `budget_split.py` (minutes, no simulation). The conclusion may survive, since the noise estimate enters only the identification term, but the number must be regenerated and the run command recorded.

### A3. VERIFIED. Uncentred interaction term makes "the magnitude is significant again" a conditional slope at opt_z = 1

`scripts/analyse_boba_robustness.py:848-849` forms `noise_x_opt_z = log_noise * log_opt_z` from raw log10 values and `log_noise_sq = log_noise ** 2`, then line 861 z-scores each column separately. In a model with an uncentred product, the coefficient on the linear `log_noise` term is the slope of log_noise where log10(opt_z) = 0, that is at opt_z = 1, inside the suite's range 0.76 to 56.8. It is not a main effect of the magnitude. The paper reads it as one. main.tex:797-799 "the magnitude is significant again beside it (−0.38 [−0.60, −0.08])", Table 6 rows "descriptors + int." and "both + int.", and Appendix G's conclusion that H1b "confirms a specification, not a fact about the error". A negative "significant" coefficient here says the cost falls with the magnitude on opt_z ≈ 1 landscapes, which nobody believes. Centre `log_noise` and `log_opt_z` before forming the product and the quadratic. R² and the frag coefficient do not change. The magnitude column and the sentence built on it will. Rerun is seconds. No test covers the interaction models.

### A4. VERIFIED. "A budget of 2.6×" is inflated by mixing two origins

`scripts/analyse_extra_runs.py:139-144` measures `extra` from the trial at which the CLEAN run first reached the k-trial target (origin ≤ k), which is the right definition of "extra". Line 183 then computes `multiplier = (k + extra) / k`. The noisy run needed origin + extra ≤ k + extra trials, so the multiplier is an upper bound with equality only when origin = k, and with a 1% tolerance and best-so-far plateaus origin < k is the normal case. main.tex:339 "a budget of 2.6×" is (25 + 41)/25. The "41 extra trials" and Table 2 are consistent with the code's definition and stand. Drop the 2.6× or compute tau/k. Also the docstring at lines 17-18 says censored runs count as T − k while the code uses T − origin, which is what the paper claims. Fix the docstring.

## B. Findings a reviewer will treat as methodological weaknesses

### B1. VERIFIED. The instrument arm discretises only the noisy post-onset ratings

`apply_sensor_error` returns exact continuous values for `iteration <= jitter_iteration` (bo_sensor_error_simulation.py:2793-2794) and `_postprocess_response` (clipping, rounding) is called only at line 2869 inside it. The clean twin is never post-processed. So Table 16's "bounded, discrete" arm at onset 21 is an instrument that switches on at trial 21 after twenty exact continuous ratings, and the 13× jump at 0.05σ in that row (0.1% to 1.3%) is the quantisation arriving as an onset, not rating noise. At onset 1 the arm measures noise plus quantisation against exact continuous. The paper half-says this ("rounding to a 0.55σ grid is itself an error"). Say it fully, and drop the onset-21 row or label it as a step change. `test_apply_sensor_error_clips_and_rounds_to_response_scale` checks only the noisy path.

### B2. VERIFIED. The Student-t arm changes the kernel as well as the likelihood

`scripts/robust_gp.py:245-246` builds `get_covar_module_with_dim_scaled_prior(ard_num_dims=d, use_rbf_kernel=False)`, a Matérn-5/2. The standard surrogate is `SingleTaskGP` default, which is RBF under the pinned botorch 0.18.1, as main.tex:245-247 states. The docstring at robust_gp.py:28-31 claims "the same kernel family" and is wrong. The Student-t row in Table 26 (−2%, −13%, price +0.2/+1.5) therefore changes likelihood, kernel and inference (variational ELBO) at once, and cannot be attributed to the heavy tail. Either set `use_rbf_kernel=True` and rerun that one arm (5 seeds × 2 acquisitions × 20 landscapes, misclick only, a few hours) or state the confound in the appendix. No test asserts the kernel.

### B3. VERIFIED. The rater-noise anchor for opticarvis uses an estimator the project's own docs call overestimated

`scripts/anchor_noise_scale.py:103-108` prefers `sd_nn_close`. That is the SD of rating differences between nearest-neighbour pairs at normalised distance at most 0.05·√d, divided by √2 (`scripts/calibrate_noise_from_data.py:111-131`). For d = 16 the threshold is 0.2 of the unit cube, so the pairs are not close and the estimate absorbs real design variance. `docs/oracle-fidelity-experiments-2026-06-12.md:17` says exactly this and puts the true intra-rater SD at 0.66 or less rather than 1.25. With 0.66/0.374 ≈ 1.8 the range in Section 4 becomes 0.74 to 1.8σ and the log-linear interpolation gives about 12 to 17% rather than 12 to 20%. Affected places are the abstract, Section 4, Table 20 and the Discussion. The paper names the nearest-neighbour (semivariogram nugget) estimator correctly at main.tex:320, and only its phrase "over repeated ratings by the same participant" is loose (corrected in the third pass). The paper attributes the upward bias only to an under-fit σf (main.tex:327-329). `calibrate_noise_from_data.preferred_sd` prefers exact re-presentations, which `anchor_noise_scale.py` never uses. Choose one estimator for both scripts and state its bias direction. Second pass D5 and third pass I8 and I13 add problems with the denominators.

### B4. VERIFIED. The floor control does not fail loudly

`scripts/analyse_boba_robustness.py:266-277` prints "FLOOR CHECK FAILED" to stderr and returns. `main()` continues and writes every CSV. `make_boba_paper_tables.py` then prints the excess cell of Table 4's floor row as the literal "0.00%" (line 186). The absolute-loss cell of that row is read from `floor_reference.csv` (line 178). The drivers redirect all output to a log. The paper says "verified to be exactly zero in every run" while the code tolerates up to 1e-9. The observed 0.000e+00 is a data value, and the only `== 0.0` test lives in `scripts/test_confirmatory_hypotheses.py:70`, a script outside pytest's `testpaths` (corrected in the third pass). Add `raise SystemExit` on failure, read the excess cell from the CSV, and write "zero to machine precision (tolerance 1e-9, observed 0.000e+00)" in the paper.

### B5. Relayed, regraded in the third pass. The "shared error cancels in a sitting" model is an assumption that is optimistic for AR(1) and drift at large k

`scripts/replay_end_of_study.py:290-314` gives every look in a sitting independent noise of SD σ (gaussian, bias, drift) or σ√(1−ρ²) (ar1) and treats the rest as a common offset. This is a modelling choice that treats a comparative sitting as one moment. If the looks are instead spread over k consecutive trials of the simulator's AR(1) process, two looks j trials apart differ with variance 2σ²(1−0.8^j). For j = 5 that is 1.34σ² against the model's 0.72σ², while adjacent looks differ less than the model assumes. Over a sitting of 16 to 30 trials the drift ramp moves by 0.3σ to σ. The Section 9 k-curve pools all four processes (`budget_split.py:105`). State the assumption and its range of validity in Appendix L, and report the k-curve separately for GAUSSIAN and BIAS, where the assumption is exact.

### B6. VERIFIED by grep. "Cautious ship rule" means two rules

Section 5 and Appendix K define it as posterior mean minus two latent SDs (`lcb2`). The replays and the budget rule use one SD (`replay_end_of_study.py:113 lcb_beta = 1.0`, `budget_split.py:97`, `replay_stopping.py:382`). Section 9's "top five candidates by the cautious ship rule" is therefore lcb1. Rename one of them.

### B7. Relayed. Section 5's "no rule that re-reads the ratings recovers it" pools all four processes and all magnitudes including 0.05σ

`decompose_regret.py:246-248` pools over bias, drift and ar1 and over 0.05σ cells, where a rule's fixed price counts as negative recovery of a tiny selection loss. Section 5's +3.9% and −8.7% are shares of the selection loss (`decompose_regret.py:191-211`). Appendix K reports the cautious rule on Gaussian error at 1σ and 5σ only, as shares of the deployed cost (+5.8% [2, 10] and +12.6% [4, 23] at 1σ, +9.7% [5, 15] and +18.5% [11, 26] at 5σ), with intervals excluding zero (corrected in the third pass). The two sections therefore differ in pooling, in cells and in denominator. The rescoring chain was traced without finding a bug (refit GP identical to the loop GP at `rescore_ship_rules.py:220-258` against `bo_sensor_error_simulation.py:3693-3701`, float64, latent posterior, tie-breaking, reproduction of the logged rule to 1e-9). State the scope of each number in its sentence.

### B8. Relayed. Appendix E's "4.7e-16" verifies the affine scaling identity, not the published maximum

`scripts/boba_multiobjective.py:196-228` checks HV_std = HV_raw / ∏σ on a fresh Sobol Pareto front. It never recomputes BoTorch's `_max_hv`. The check is vacuous for DH2 (both zero). "No run beats its published maximum hypervolume" (main.tex:1052) is asserted by no script. The MO headroom screen is 0.15 in `analyse_boba_mo.py:60`, not the 0.10 the text calls "the same screen". Outcome unchanged (DH2 out, Penicillin 0.197 in). Fix the sentences.

### B9. Relayed. Known-noise arm details

`known_noise_variance` returns σ² per point for ar1 and drift (bo_sensor_error_simulation.py:2094-2132). σ² is the true marginal variance of both noise components. What an iid `train_Yvar` cannot express is the AR(1) correlation and the drift's mean ramp (corrected in the third pass). The arm ran GAUSSIAN only (run_boba_followups.ps1:99-104), so no reported number is affected. The arm's clean twin gets `train_Yvar = 1e-6`, a near-interpolating GP, so Table 9's Δ is treatment against its own twin minus reference against its own twin. That is defensible and needs one sentence. The prose "3% or less at 1σ and above" holds only for the excess-weighted pool over both onsets. The onset-20 rows in `tables/known_noise.tex` read +17% and +9%.

### B10. Relayed. Confirmatory script deviations beyond the one admitted

`scripts/test_confirmatory_hypotheses.py`. H3a over 8 conditions not 20 benchmarks (admitted). The BH correction for H3 is `multipletests([p_a, p_a])`, a no-op (line 262-263). ## D. Verified correct

Error processes match Equations 1 to 4 including the AR(1) stationary first draw and the drift denominator (`apply_sensor_error`, 2782-2870). Onset indexing: `jitter_iteration = 0` corrupts iteration 1, `= 20` corrupts iteration 21 first. RNG streams: candidate proposals from `default_rng(seed)`, response noise from a separate SeedSequence keyed on (seed, acquisition, onset, magnitude, process), never touched by the clean twin; random and sobol never call the GP, so their excess is identically zero by construction. Incumbent: `posterior_mean` default, `observed_max` alternative; UCB, qUCB and qNEI never read `best_f`. GP: `SingleTaskGP` with `Normalize` and `Standardize`, `train_Yvar` only under `--observation-noise known`, float64 throughout. Standardisation over a 2^16 scrambled Sobol sample, opt_z = (y_opt − mean)/std with y_opt = max(published, verified). Input error: slip and misclick draw from the noise stream, the deployed design is scored at the recorded location. Pairing in `evaluate_research_question.py:304-340` merges on dataset, acquisition, seed, logged oracle name, onset and run length; the post-onset window is aligned across twins (checked on synthetic logs). Power law: raw excess in SDs (not divided by opt_z), quasi-Poisson estimating equations solved by Newton with step-halving (score residual 3.5e-13 on a synthetic grid, identical to fsolve), BCa with jackknife acceleration reproducing scipy's implementation to 1e-16, 2000 landscape resamples. frag: 256 Sobol candidates, 4000 error draws, common random numbers between exact and pilot versions, keys matching the lookup. Decomposition arithmetic: 0.212 + 0.135 = 0.346, 38.9% and 61.8% as ratios of landscape means with landscape bootstrap; clean selection loss asserted zero. Adaptations estimand: cost, gain, price per paired cell, ratio of landscape means, landscape bootstrap, Wilcoxon on per-landscape gains, BH within arm × response. Rescoring GP identical to the loop GP; reproduction of the logged rule to 1e-9. Tournament and confirmation replays keep budget parity, the confirmation test is a one-sided paired t at α = 0.05, false claim = claim ∧ ¬(f(D) > f(C)). GLR statistic is the correct maximised LLR. Input-error mechanism tables restrict to tasks complete in every arm and assert the paired gap. Drivers: every variant that changes the clean run has its own directory; every reference row is restricted to the arm's acquisitions, seeds and error process; the guard in `bo_synthetic_error_simulation.py:494-545` tracks only minimum distance, the input-uncertain acquisition, relevance pursuit, the rater model and the halo model, so the Student-t likelihood, the noisy-input GP, replicate-first, final re-rate and the inference rule are kept apart only by the drivers' choice of directory (corrected in the third pass). Run counts (79,200; 76,800; 64,000; 2,000; 12,800; 4,800; 1,680; 960; 560) are all arithmetically consistent with the design. All `\ref`, `\input` and `\cite` targets resolve.

## E. What to do, in order

The ordered action list, with corrected rerun recipes, is in `README.md` of the handover folder under "Ordered actions". Two corrections to the earlier list matter. A rerun must go into a fresh output directory, because the drivers skip completed directories and resume by file name. `budget_split.py` must be rerun without `--summary-only` and with the k-grid and sitting ρ that produced the paper, which are not the defaults.
