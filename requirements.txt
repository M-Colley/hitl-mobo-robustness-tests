# Two floors are tighter than "the oldest version that runs", because a looser
# one installs a stack that takes a different numerical path (checked 2026-10-09):
#  * BoTorch is the commit the runs used. The PyPI release 0.18.1 predates
#    BoTorch PR #3328, which raised SCIPY_UNTESTED_VERSION to 19, so with scipy
#    1.18 it optimises the acquisition restarts jointly instead of one by one
#    and every logged run differs from trial 8 on.
#  * scipy stays below 1.19 on this BoTorch build: at 1.19 the same gate
#    switches the optimiser path back.
# torch 2.14 changed the gradient of clamp at its bound (PR #191142), which
# gpytorch's squared distances hit, so runs under torch >= 2.14 are not bit for
# bit the logged ones; scripts/checks/version_sensitivity.py shows the reported
# quantities do not move.
